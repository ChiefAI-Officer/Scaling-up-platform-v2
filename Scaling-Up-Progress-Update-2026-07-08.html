1 · Catch a bad import before anyone notices

Historical imports are powerful but quiet — a bad file could fail with only a line buried in a server log. This adds an in-app view so import trouble surfaces where an admin will actually see it.

Admin → Assessments → Observability · records automatically, no setup

Import health, in the app instead of the logs

The automated import-watch now reports its actual decisions and its own health on a page in the admin area, rather than only emailing on failure.

The silent gaps are closed

Two paths used to leave no trace at all — previewing an import, and files the system refuses up-front (wrong assessment, bad shape). Both are now recorded, across every pre-commit check in both import routes.

Silence means healthy

The panel ships empty and only fills in when an import actually hits a problem — so a blank page is the good state, and a populated one is your early warning.

Live on production

2 · The editor stops showing numbers that were never real

The template editor's scoring screen carried a leftover "peer benchmarks" card with hard-coded, invented values — for a feature that already exists for real elsewhere (the peer- averages panel shipped in Wave S). An admin editing a template should never see fabricated data presented as if it's live. Removed it, plus a dead button that did nothing.

◼ Before
A disabled "Peer Benchmarks" card showed fake figures (2.4 / 1.8 / 2.7), and a "Preview as Respondent" button was greyed out with a "coming soon" note that never arrived.
✓ After
The scoring tab ends cleanly. Real peer-average authoring lives in its own panel (Wave S) — the only place peer numbers can be entered, and only real ones.
Built & staged — one switch from live

3 · Personalized recommendations, now in the results email

Until now, the answer-driven "what to work on next" recommendations you author appeared only on the on-screen report. This adds them to the results email — for both the person assessed and their referring coach, on every instrument type (scored and qualitative). It reads the recommendations already frozen onto each submission, so issued reports never drift.

Sample · scored results email — rendered from the shipped code

The recommendations now ride along in the email

A real render, not a mockup: the full scored report followed by a "What to work on next → Your recommendations" block, pulling each person's answer-driven recommendations — including the slider-based ones the on-screen report leaves out. This is the sample I'd send you to review before switching it on.

Sample · qualitative (LVA) results email

For qualitative instruments, recommendations lead — answers follow

Same feature, different shape: on a qualitative report the recommendations render before the person's own answers, so they're the first thing read and never get cut off by email length limits.

Recommendations reach people where they read Staged

The email now carries the same recommendations as the report — including the slider-based ones, which matters for the bigger scored instruments. Built and in production, but behind an off switch until you say go.

Authoring gets a "test a value" preview Live now

When you write a recommendation in the editor, you can type a sample answer and instantly see which recommendation text would fire — using the exact same logic a real submission runs, so what you preview is what a client will get. No more authoring blind.

Why it's still off

The results email is a live send path — flipping this on changes what real people receive the moment it's enabled. So it's staged deliberately. Say the word and I'll send you a real sample email first (one scored, one qualitative) before it reaches any client.

Live on production

4 · A small editor fix

Sections added while editing a template weren't being saved with their position, so a new section could silently fail to publish or lose its order. Fixed — new sections now publish and keep the order you put them in.
