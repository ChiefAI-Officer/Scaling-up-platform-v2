## Feature-state and delivery matrix

Precedence is `policy unavailable` > `limiter unavailable` > `KILL` > `CANARY` > `ON` > `OFF`. The always-on lease and same-mailbox suppression apply in every row.

| Effective state | Attribution persistence | New coach notification | Taker / Scaling Up mail | Coach surfaces | Already queued feature rows |
| --- | --- | --- | --- | --- | --- |
| PRE-ISSUANCE `OFF` or canary miss | Preserve the pre-wave legacy email-only field; do not create stable Public-lead ownership and do not accept/generate `?ref=` | Preserve legacy content except self-mailbox suppression | Preserve current content | Hidden; admin contract unchanged | Drain legacy rows through the lease |
| `CANARY` hit or `ON`, policy ready, limiter healthy | Validate `?ref=`/legacy alias in-transaction and snapshot stable ownership | Enqueue concise authenticated notification unless same mailbox | Enqueue taker report with currently eligible Coach CTA plus one Scaling Up summary | Enabled only for eligible cohort/owners; admin additions enabled | Drain after send-time provenance and eligibility checks |
| Pre-issuance `KILL` | Same as PRE-ISSUANCE `OFF` | Legacy behavior | Legacy behavior | Hidden | Cancel only feature-provenance rows; legacy rows drain |
| Post-issuance `KILL` | Continue resolving issued keys and persist safe dormant ownership for compatibility | Do not enqueue; cancel/purge pending, held, or leased feature Coach rows and invalidate their lease token | Taker rows are re-rendered with generic finder; Scaling Up summary remains singular | Hidden; report/list/export deny | Re-enable never revives cancelled Coach rows; an audited replay must re-render and reauthorize |
| Policy unavailable | Do not create or expose coach ownership; submission is Scaling Up-owned even if a key resolves | Do not enqueue | Taker uses generic finder; Scaling Up summary remains singular | Hidden/deny; admin sees no coach attribution | Cancel/purge every feature row containing coach-derived PII; legacy PRE-ISSUANCE behavior is unaffected while the feature is OFF |
| Distributed limiter unavailable during `CANARY`/`ON` | Discard candidate attribution and persist the submission as Scaling Up-owned; no later coach reassignment from this request | Do not enqueue | Only while an independently locked, configuration-approved global and per-campaign held-backlog budget has capacity, place taker and Scaling Up rows in `HELD`; otherwise reject before persistence with a retryable response | Excluded from coach count/list/report/export | Never release Coach rows; bounded audited release re-renders generic taker content and releases only those two roles after dependency recovery |

Keys are not issued until policy and limiter launch gates pass. Once any key is issued, parser compatibility is a permanent floor: deployed code may not stop understanding issued keys. When policy and limiter are healthy, a post-issuance presentation/access/notification kill still captures dormant ownership so valid attribution is not silently lost. Policy or limiter failure is the explicit exception: ownership is irreversibly forfeited for that request and remains Scaling Up-owned, because retaining a promotable candidate would violate the fail-closed privacy and abuse boundary. A canary miss always follows the PRE-ISSUANCE `OFF` row and never partially enables new persistence or API contracts.
