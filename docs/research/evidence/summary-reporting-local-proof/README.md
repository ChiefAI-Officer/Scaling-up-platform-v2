# Summary Reporting local proof and rollout checklist

This is **local evidence, not a production launch record**. Global enablement,
private-store provisioning, deployment, the exact campaign canary and product
owner acceptance of live screens/PDF are still pending.

## Reproduce the local proof

Run from the app directory `src/`, with Node 20, local PostgreSQL 16 binaries in
`/opt/homebrew/bin`, Poppler (`pdftoppm`, `pdftotext`) and Playwright Chromium:

```sh
PATH=/opt/homebrew/opt/node@20/bin:$PATH npx playwright test e2e/summary-reporting.spec.ts --project=chromium --config=playwright.summary-reporting.config.ts
```

Add `--headed` for the captured native-PDF visual proof. Full Chromium (not the
headless shell) is selected explicitly; see the visual review for engine limits.

The separate config deliberately does not reuse a developer server. The fixture
starts PostgreSQL on an unused loopback port and a real Next development server
on another unused loopback port. All data is synthetic/de-identified. Coach and
admin authenticate through the real bcrypt/NextAuth credential path; demo auth
is off. The app receives an explicit test-only environment, not the original
checkout's environment. No production database, Vercel resource or live record
is used.

The complete historic migration chain cannot bootstrap an empty database:
`20260226000000_feb25_call_revisions_schema` fails with PostgreSQL `42P01`,
`relation "categories" does not exist`. The fixture materializes the pre-tracer
schema from `a57b9c04^`, initializes only that empty local database, then executes
the **unchanged** `20260827090000_add_summary_reports/migration.sql` with
`psql -v ON_ERROR_STOP=1`. This proves the tracer migration and its constraints,
not successful replay of the historical chain. A shallow checkout must include
that baseline commit to run this test.

The production snapshot, renderer, Prisma adapters, authorization, audits and
Blob SDK wrapper run unchanged. Only the external Blob **transport** is a test
double: a fake token and exact private-store host are intercepted, bytes are
stored in the fixture's temporary directory, and non-loopback network access is
denied. Its private-access option and object paths are checked. This is not proof
of actual Vercel Blob privacy, retention, CDN behavior or network availability.
The development limiter is explicit; a separate unit regression proves missing
distributed configuration fails closed in production. Actual Redis operation
remains a canary prerequisite, not an inferred pass from a development fallback.

The input contains all 61 scored Scaling questions, accepted de-identified CEO
answers, and deterministic Team answers (all 4 / all 8), scored by the production
scorer. Optional/background identity fields are omitted from this local fixture.
Creation time/request IDs are generated by the real lifecycle, so artifact hashes
differ between runs; the proof checks that each stored artifact remains exactly
the same after retry, view/download and a later submission.

Screenshots named `*-desktop.png` use 1440×1000; `*-mobile.png` are full-page
captures from a 390×844 viewport. `*-mobile-viewport.png` preserve the actual
390×844 visible viewport. Full-page images can be wider because the existing
campaign respondent table overflows on small screens. Do not treat the wider
full-page image as a mobile viewport size. PDF page rasters are the actual bytes
downloaded through the authorized route, not a mock HTML report.

See [renderer and lifecycle visual review](../summary-reporting-scaling-ceo-full-renderer-v1-review.md)
for findings, differences and the live visual gate.

## Recorded local results (2026-08-27)

  portal test intentionally logs `simulated eligibility failure`; no test failed.
- Affected artifact/wizard/host/strict-limiter gate: **4 suites / 59 tests passed**,
  including same-name historical Review provenance and missing production Redis.
- Headed Playwright: **4/4 passed**, 59.3s. Both actors independently create one
  report, retry idempotently, view/new-tab/download, and preserve input/artifact
  hashes after another submission. Unauthenticated middleware returns 307 to
  `/api/auth/signin` (not a PDF); expired destination access returns 404;
  revoked cross-campaign creation returns concealed `source_unavailable` 422.
  Existing destination-authorized artifacts remain available after source-only
  revocation, as designed. Local same-length byte corruption returns private
  no-store 503; restored bytes pass again. PostgreSQL rejects updates/deletes
  of reports/sources and both source-ID / role-position duplicates.
- Migration safety: **43 migrations**, no unapproved destructive operations,
  exit 0. This static gate is distinct from the real tracer-SQL application
  described above and does not repair the historical bootstrap gap.
- Changed-file ESLint: exit 0. The first build exposed a fixture environment
  type mismatch (missing required `NODE_ENV` in two subprocess allowlists);
  both now explicitly set test-only `development`.
- Node 20.20.0 Turbopack production build: exit 0, compiled in 14.5s, all 92
  static pages generated. It ran with an empty environment except local PATH,
  HOME, CI and telemetry-off. Nonfatal output: multiple-lockfile inferred-root
  warning, existing middleware-convention deprecation, seven missing Inngest
  event/signing-key warning pairs, and three missing-DATABASE_URL static-data
  errors (category/workflow/contact). No application credentials were loaded.
  This is the actual build's TypeScript check, not a claim that the separate

## External rollout — NOT RUN

1. Complete whole-branch review and resolve material UI/PDF findings. Keep
   `SUMMARY_REPORTING_ENABLED=0`, `SUMMARY_REPORTING_CANARY` empty and
   `SUMMARY_REPORTING_KILL=0` for initial deployment.
2. Provision a **dedicated private** Vercel Blob store. Connect Preview first and
   set its token as `SUMMARY_REPORT_BLOB_READ_WRITE_TOKEN`; never reuse the public
   attachment store token. Do not expose this server-only token to clients.
   Verify private access using the actual store; a guessed or copied object URL
   must not disclose a PDF without authorization.
3. Configure and verify the existing distributed limiter with `REDIS_URL` or
   `KV_URL`. Missing/unavailable storage or limiter is an operational failure,
   not permission to enable a public store or production in-memory fallback.
4. Ship through the protected PR flow with Build and Migration Safety Gate.
   Apply the additive tracer migration. Verify `/api/health`, both campaign
   detail hosts and the unchanged `/assessments/[id]/report` path while off.
5. Set `SUMMARY_REPORTING_CANARY` to one **exact approved Scaling campaign ID**.
   Keep global off. With authorized coach/admin actors create one report; confirm
   one row on retry, exact selected source order, stored input hash and artifact
   SHA-256, private/no-store delivery, strict creation/view/download audits,
   destination-currency revocation, and access denied when unauthenticated.
6. Verify framing after the actual deployment: only
   `/api/assessment-campaigns/:id/summary-reports/:reportId/artifact` receives
   `X-Frame-Options: SAMEORIGIN`; other pages retain `DENY`. Next config and
   `vercel.json` contain the same narrow exception because the global configured
   header otherwise overrides the route's response header. Confirm live modal
   PDF paint, new-tab and download behavior; local headers do not prove CDN
   precedence or the deployed CSP.
7. Compare live PDF headings, all 61 questions, CEO naming, anonymous Team
   appendix, palette, hierarchy and representative desktop/mobile pages with
   the tracked accepted baseline and local rasters. Get explicit product-owner
   acceptance of the actual canary screens/PDF before global enablement.

**Rollback:** set `SUMMARY_REPORTING_KILL=1` and deploy the environment change.
Kill overrides global/canary state and hides the new UI/routes. Do not delete or
recompute immutable reports, remove their migration, or alter the existing group
report route. Recheck health and both hosts after rollback.

**Later family slices remain unimplemented:** Scaling Condensed CEO and Self
Comparison; LVA CEO Full; separate QSP v1/v2 CEO Full and configured Remarks;
Rockefeller Team-only Full. Each needs its own approved executable plan against
this shared lifecycle. No report hub, rename/delete/share or participant access
is introduced.
